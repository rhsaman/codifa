# deep-research

Use when the user needs a well-researched answer, report, or overview on a topic they don't know deeply.

## Process

1. **Clarify the question.** What exactly needs to be known? For what decision or deliverable? Scope (breadth vs. depth) and deadline.
2. **Plan queries.** Break the topic into 3-6 sub-questions. Plan search queries per sub-question, mixing broad and specific phrasings.
3. **Gather sources.** Search, read, and collect: primary sources when possible, reputable secondary sources otherwise. Note dates — recency matters for fast-moving topics.
4. **Evaluate credibility.** For each source ask: who publishes this, what's their expertise, is there evidence, does it conflict with other sources? Prefer peer-reviewed / official / expert sources over blogs and anonymous posts.
5. **Synthesize, don't stack.** Combine findings into a coherent answer. Highlight agreements and conflicts between sources. Flag uncertainty explicitly ("sources disagree on X").
6. **Cite.** Reference sources inline or in a list so claims can be checked. Distinguish facts from interpretation.
7. **Answer first.** Lead with the direct answer to the user's question, then the evidence trail.

## Deliverable shape

- Direct answer (2-5 sentences) → key findings with sources → gaps/uncertainty → suggested next steps.
