# project-planning

Use when starting a project, feature, event, or any multi-step goal that needs structure and sequencing.

## Process

1. **Define the outcome.** What does done look like? Write a clear objective with measurable success criteria.
2. **Break it down.** Decompose into milestones, then tasks small enough to complete in one sitting. Each task: one action, a clear deliverable.
3. **Sequence and estimate.** Order tasks by dependencies. Estimate effort and add buffer (tasks usually take longer than expected).
4. **Assign ownership.** For teams: one owner per task. For solo work: still note who/what depends on each piece.
5. **Identify risks.** What could go wrong or block progress? List top 3-5 risks and a mitigation for each.
6. **Set checkpoints.** When to review progress (e.g., end of each milestone) and what signals success or needs adjustment.
7. **Keep it lightweight.** Plans change — record decisions, but don't over-engineer. Revisit and update as reality unfolds.

## Deliverable shape

- Objective & success criteria → milestones → task list with estimates → owners → risks → review dates.
