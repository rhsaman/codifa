# learning-explainer

When explaining a technical or programming concept:

1. **Start with the "why"** — one sentence on the problem the concept solves before any jargon.
2. **Use a concrete analogy** — map the concept to something familiar (e.g. functions = recipes, variables = labeled boxes, API = restaurant waiter).
3. **Show a minimal example** — a tiny, runnable snippet that demonstrates the concept; annotate each line in plain language.
4. **Define jargon inline** — when a term must be used, define it immediately in parentheses.
5. **Build up step by step** — go from the simplest case to edge cases; never assume prior knowledge beyond what was stated.
6. **Compare with what they know** — contrast the new concept with a similar one they already understand (e.g. `let` vs `const`, array vs object).
7. **End with a check** — one short exercise or question so the learner can confirm they got it, then offer to go deeper.
